目标场景和背景说明

1、为规范待遇款从待处理到最终支付或抵扣的全流程管理，实现待遇处理方式确认、材料审核、审批流转、支付执行的全生命周期追踪，确保待遇款处理合规、高效、可追溯，满足财务支付与客户服务需求。

2、系统需支持根据产品类型（代理类 / 外包派遣类）限制处理方式（支付客户 / 支付员工 / 账单抵扣），关联银行流水与账单数据完成支付或抵扣操作，并通过日志记录所有处理动作，为流程审计与问题排查提供支撑。

3、支持批量操作（批量推送审批、批量审批）减少重复操作，通过状态自动流转（待处理→待送审→审批中→待支付 / 账单抵扣中→已办结）提升流程效率，同时处理支付失败等异常场景。


功能说明

【待遇处理】用于实现待遇款的处理方式确认、材料上传、审批流转、支付 / 抵扣执行及异常处理，核心功能包括：

待遇处理操作：根据产品类型选择处理方式（支付客户 / 支付员工 / 账单抵扣），上传对应材料，完成处理信息录入。

审批流转管理：支持单条 / 批量推送审批、单条 / 批量审批，实现状态从待送审→审批中→待支付 / 账单抵扣中的流转。

支付与抵扣管理：审批通过后生成应付记录（支付类）或关联账单抵扣（抵扣类），处理支付失败场景（重新生成应付）。

异常处理：支持被驳回记录重新处理、审批中记录撤销审批、支付失败记录重试等操作。

日志追踪：自动记录所有处理动作（处理、推送审批、审批、支付等），清晰呈现流程变更轨迹。



字典说明：

1. 申报类型

养老：含养老金、独生子女父母养老补贴等养老相关待遇。

医疗：含医疗费用报销、医疗康复补贴等医疗相关待遇。

工伤：含工伤医疗费用、伤残津贴等工伤相关待遇。

生育：含女职工生育津贴、生育医疗费用等生育相关待遇。

失业：含失业补贴、失业救济金等失业相关待遇。

雇主险：含雇主责任险覆盖的医疗费用、伤残赔偿等待遇。

团体意外险：含意外身故赔偿、意外住院津贴等团体意外险待遇。

商业医疗保险：含商业医疗险覆盖的住院费用报销、重疾补贴等待遇。

2. 状态

待处理：专员审批通过后，需客服确认处理方式并上传材料的状态。

待送审：已确认处理方式并上传材料，待提交审批的状态。

审批中：已提交审批，审批流程未完成的状态。

被驳回：审批未通过，需重新处理的状态。

待支付：审批通过且处理方式为 “支付客户 / 支付员工”，待生成应付记录的状态。

支付失败：应付记录生成后支付未成功，需重新处理的状态。

账单抵扣中：审批通过且处理方式为 “账单抵扣”，待完成抵扣的状态。

已办结：支付成功或抵扣完成，流程结束的状态。

3. 处理方式

支付客户：向客户账户支付待遇款（仅代理类产品支持）。

支付员工：向员工个人账户支付待遇款（仅外包派遣类产品支持）。

账单抵扣：通过客户应付账单抵扣待遇款（仅外包派遣类产品支持）。

4. 所属产品

岗位外包：外包派遣类产品，支持处理方式为 “支付员工”“账单抵扣”（后期可通过子流程开通别的方式：下个版本做）。

薪资代发：代理类产品，支持处理方式为 “支付客户”（后期可通过子流程开通别的方式：下个版本做）。


权限说明

页面权限：仅客服、审批人及超级管理员有权进入本页面。

操作权限：

客服：可执行 “处理”（确认方式、上传材料）、“推送审批”“批量推送审批” 操作（限待处理、待送审状态），生成应付”（限支付失败状态）、“撤销审批”（限待支付、账单抵扣中、支付失败状态）。

审批人：可执行 “审批”“批量审批” 操作（限审批中状态）。

超级管理员：拥有所有操作权限。

限制规则：已办结状态记录不可执行任何操作；审批中状态仅可执行审批或撤销审批（未终审时）。


数据说明

待遇金额：取自待遇申报记录的应发金额，为处理金额上限。

已支付 / 抵扣金额：取自支付记录或账单抵扣记录的实际金额，累计不可超过待遇金额。

状态：当前状态（如 “待处理”“审批中”），随操作实时更新。

创建时间：取待遇处理记录首次创建的系统时间，精确到秒。

审核通过时间：取审批人最终 “同意” 操作的系统时间，仅待支付 / 账单抵扣中 / 已办结状态有值。

办结时间：取支付成功或抵扣完成的系统时间，仅已办结状态有值。

办理材料：记录上传的材料名称及路径，支持在线查看。

交互说明

查询

查询自动触发条件：下拉框选项改变时自动触发查询；文本框输入内容（姓名、身份证、所属客户）后回车自动触发查询，减少用户点击操作。

表头支持查询字段：【姓名、所属客户、身份证、状态（待处理 / 待送审 / 审批中 / 被驳回 / 待支付 / 支付失败 / 账单抵扣中 / 已办结）、申报类型、所属产品】。

排序

表头支持排序字段：【创建时间、待遇发生日期、待遇金额、审核通过时间】，点击表头字段切换升序 / 降序。

默认创建时间倒叙。


状态流转规则

待处理→待送审：完成 “处理” 操作并点击 “保存并推送审批” 后触发。

待送审→审批中：执行 “推送审批” 或 “批量推送审批” 操作后触发。

审批中→待支付 / 账单抵扣中：审批人选择 “通过”，根据处理方式自动触发。

审批中→被驳回：审批人选择 “驳回” 并填写原因后触发。

待支付→支付失败 / 已办结：支付操作后根据结果触发（失败则为支付失败，成功则为已办结）。

账单抵扣中→已办结：抵扣完成后触发。

支付失败→待支付：执行 “生成应付” 操作后触发。


待遇处理操作

（待处理状态）流程：点击 “处理”→选择处理方式（根据所属产品限制选项，如岗位外包仅显示 “支付员工”“账单抵扣”）→上传材料（劳动合同、确认邮件截图等，支持.pdf、.doc 等格式）→填写备注→点击 “保存并推送审批”。

材料要求：代理类产品需上传 “劳动关系证明材料”“待遇支付委托书”,也可以支持自定义额外的材料；

外包派遣类产品需上传 “劳动合同”“确认邮件截图”。

交互：提交后显示加载状态，成功则状态更新为 “待送审” 并生成日志；失败则保留页面并提示原因（如 “未上传必填材料”）。

日志文案：“对待遇处理记录进行处理：处理方式{处理方式}，上传材料 ：{材料名称列表}，{文件名称列表}，当前状态：待送审。”

交互2：如果是保存并送审，直接触发【推送审批】的状态和日志


推送审批 / 批量推送审批

单条推送：在待送审状态点击 “推送审批”→确认弹窗（“确认推送该记录至审批流程？”）→确认后状态更新为 “审批中”。

批量推送：勾选多条待送审记录→点击 “批量推送审批”→确认弹窗→确认后批量更新状态为 “审批中”。

日志文案：单条：“将待遇处理记录推送至审批流程，当前状态：审批中。”


审批 / 批量审批

单条审批：在审批中状态点击 “审批”→查看待遇信息及材料→选择 “通过” 或 “驳回”（驳回需填原因）→点击 “提交”。

批量审批：勾选多条审批中记录→点击 “批量审批”→为每条选择 “通过” 或 “驳回” 并填写意见→点击 “提交”。

交互：提交后显示加载状态，成功则更新状态（通过→待支付 / 账单抵扣中；驳回→被驳回）并生成日志；失败则提示原因。

日志文案：

通过：“审批通过待遇处理记录，审批意见：{意见}，当前状态：${目标状态}。”

驳回：“审批驳回待遇处理记录，驳回原因：{原因}，当前状态：被驳回。”

交互2：如果是支付类的，审批通过，静默触发【生成应付】


生成应付

（支付失败状态）流程：点击 “生成应付”→系统自动填充付款信息（收款方、金额等）→确认信息→提交生成应付记录。

交互：提交后显示加载状态，成功则状态更新为 “待支付” 并生成日志；失败则提示原因（如 “收款信息错误”）。

日志文案：“为待遇处理记录生成应付记录，金额{待遇金额}，当前状态：待支付。”


撤销审批

适用状态：待送审、审批中、待支付、账单抵扣中、支付失败。

流程：点击 “撤销审批”→填写撤销原因→提交→确认弹窗→确认后执行撤销。

状态回退规则：审批中→待送审；待支付 / 账单抵扣中 / 支付失败→待送审。

日志文案：“撤销待遇处理记录的审批流程，撤销原因：{原因}，当前状态：待送审。”


合并处理

适用状态：待处理。

流程：选择【只有同员工，同客户，同待遇享受账套，同待遇项目且是待处理的记录】点击 “合并处理”→→确认弹窗→确认后执行合并。

状态回退规则：可以从新拆分金额。

日志文案：“把{员工}的款项金额进行合并处理，合并后的金额为{待遇金额}，当前状态：待处理。”


分拆款项

适用状态：待处理。

流程：点击 “分拆款项”→填写金额→确认后执行合并。

状态回退规则：可以选择合并处理。

日志文案：“把{员工}的款项金额进行分拆处理，分拆后的金额由{原金额}为{新的待遇金额}，当前状态：待处理。”

新纪录日志文案：“把{员工}的款项金额进行分拆处理，分拆后的金额由{原金额}为{新的待遇金额}，当前状态：待处理。”


查看操作

功能：点击 “查看” 可查看待遇基本信息（姓名、金额、申报类型等）、处理记录（处理方式、材料）、变动日志（所有操作历史）。

交互：弹窗展示信息，支持关闭弹窗返回列表。

日志文案：无（查看操作不生成日志）。


其他交互

无特殊情况，按原型开发即可不做任何说明。
